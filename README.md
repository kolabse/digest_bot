# Project Digest Bot

Бот читает `project-digest.md` из GitHub или GitLab и отправляет нужную дневную секцию в
Telegram по расписанию. Настройка рассылок выполняется диалогом с ботом.

## Что реализовано

- несколько независимых рассылок и адресатов в одном экземпляре;
- временная приостановка и возобновление сохранённых рассылок;
- адресат Telegram — личный чат с ботом либо группа, где запущен `/setup`;
- настройка источника, Git ref, часового пояса и времени через `/setup`;
- чтение публичных и приватных GitHub-репозиториев и разрешённых self-hosted
  GitLab-инстансов без передачи токена в Telegram;
- SQLite-хранилище и защита от повторной отправки одной рассылки за одну дату;
- ограниченные повторные попытки с сохраняемым между перезапусками backoff;
- восстановление пропущенной отправки после краткого простоя в пределах того же окна;
- вариативное вступление с корректной формой «сегодня» или «вчера»;
- завершающий текст, зависящий от количества изменений в дайджесте;
- вариативное запасное сообщение об отдыхе команды, если секции за дату нет или в ней нет пунктов;
- разбиение длинных сообщений под ограничение Telegram.

Ожидаемый формат соответствует навыку `maintain-project-digest`:

```markdown
# Дайджест проекта

## [2026-08-20]

### Доработки

- Добавлена новая возможность.
```

## Правило выбора даты

Время всегда интерпретируется в часовом поясе конкретной рассылки.

- 00:00–13:59 — отправляется дайджест за вчера;
- 14:00–19:59 — рассылка запрещена, `/setup` не сохранит такое время;
- 20:00–23:59 — отправляется дайджест за сегодня.

Границы заданы как полуинтервалы, поэтому ровно 14:00 уже относится к периоду
без отправки, а ровно 20:00 — к вечернему окну.

## Запуск

1. Создайте бота через `@BotFather` и получите токен.
2. Скопируйте `.env.example` в `.env`, задайте `TELEGRAM_BOT_TOKEN`.
3. Рекомендуется задать `BOT_ADMIN_USER_IDS`: без него любой пользователь,
   нашедший бота, сможет создать личную рассылку. В группе `/setup`, `/edit`, `/list`,
   `/preview`, `/pause`, `/resume` и `/delete` доступны только администраторам группы.
4. Для приватного GitHub-репозитория создайте fine-grained token с read-only
   доступом к Contents. Для GitLab используйте project/group/personal access token
   со scope `read_repository` или `read_api`. Положите токен в переменную окружения,
   например `GITHUB_TOKEN` или `GITLAB_TOKEN`. В диалоге указывается имя переменной,
   не значение секрета. GitLab-хост также должен быть перечислен в
   `GITLAB_ALLOWED_HOSTS` через запятую.
5. Запустите:

```shell
docker compose up -d --build
```

Если `api.telegram.org` недоступен напрямую, задайте `TELEGRAM_PROXY_URL` в
`.env`, например `http://127.0.0.1:3128` или `socks5://127.0.0.1:1080`. Прокси
используется и для обычных Bot API-запросов, и для long polling.

Локальный запуск для разработки:

```shell
python -m venv .venv
.venv/Scripts/pip install -e ".[dev]"
.venv/Scripts/digest-bot
```

При запуске бот автоматически применяет последовательные миграции SQLite в одной
транзакции. База версии v0.1.0 распознаётся и получает номер схемы без пересоздания
таблиц и потери сохранённых рассылок или доставок. Если база имеет неизвестную либо
более новую схему, запуск останавливается без частичного обновления. Перед обновлением
production-экземпляра рекомендуется остановить бот и скопировать файл из `data/` в
резервное хранилище.

Ошибки сети и временные ограничения API повторяются до пяти раз с экспоненциальной
задержкой, но только внутри исходного утреннего или вечернего окна. Количество попыток
и задержки настраиваются переменными `DELIVERY_MAX_ATTEMPTS`,
`DELIVERY_RETRY_INITIAL_SECONDS` и `DELIVERY_RETRY_MAX_SECONDS`. Ошибки конфигурации,
доступа и некорректного адресата сразу переводят доставку в состояние `failed`.
Срок владения выполняющейся попыткой задаётся `DELIVERY_CLAIM_LEASE_SECONDS`;
значение должно превышать ожидаемую длительность чтения и отправки одного дайджеста.
Доставка имеет семантику at-least-once: если Telegram принял сообщение, а процесс
завершился до записи результата в SQLite, повторная попытка может создать дубликат.
Для сообщений из нескольких частей повтор может заново отправить уже доставленные части.

В Telegram используйте `/setup`. Чтобы адресатом была группа, добавьте туда бота
и запустите команду в самой группе от имени администратора. Команды `/list`,
`/edit ID`, `/pause ID`, `/resume ID`, `/preview ID` и `/delete ID` управляют
рассылками только текущего чата. Приостановка запрещает новые запуски по расписанию,
но не отменяет отправку, которая уже началась; проверка через `/preview` остаётся доступной.
При редактировании каждый параметр можно заменить либо оставить без изменений
одноимённой кнопкой. Канал доставки и чат-адресат существующей рассылки не меняются.

## Архитектура расширения

`DeliveryService` не зависит от Telegram и выбирает реализацию по полю `channel`.
Новый канал реализует протокол `DeliveryChannel.send(target, message)` и
регистрируется в словаре каналов при запуске. Модель `target` строковая, поэтому
может представлять chat ID, email-адрес или идентификатор группы получателей.
